# Published seed schemas

The JSON Schema Draft 2020-12 files in `v1/` describe both YAML and JSON documents:

- `manifest.schema.json`: shared `micharisma-seeds/v1` envelope and recursively nested groups, independent of an app catalog.
- `ala.schema.json`: AthleteAce entity types, local definition codes, permitted attributes, and association reference names.
- `entity-sequences.schema.json`: optional numeric sequence registry and terminology names.

The catalog schema deliberately does not require relationships on each record: they can be inherited through scope. Model validations, reference resolution, and replay policies still belong to the app. Ascent can use the shared envelope while its model contract evolves; this publication does not install or finalize an Ascent adapter.

`ala.contract.json` is generated by AthleteAce from its live importer allowlist, protected attributes, model columns, enums, and associations. It is the input for the catalog schema, not a seed manifest. Do not edit generated files by hand.

## Maintainer regeneration

From AthleteAce, after preparing the test database to match the intended model schema:

```sh
RAILS_ENV=test bundle exec rails seeds:schema_contract
```

Then from `lib/micharisma_seeders` (the private build tool, not needed by contributors):

```sh
bundle install
bundle exec ruby exe/export-seed-schemas --catalog ../../db/seeds/athlete_ace_data/schemas/ala.contract.json --output ../../db/seeds/athlete_ace_data/schemas/v1 --base-url https://raw.githubusercontent.com/mikeymicrophone/athlete_ace_data/main/schemas/v1
bundle exec ruby exe/export-seed-schemas --catalog ../../db/seeds/athlete_ace_data/schemas/ala.contract.json --output ../../db/seeds/athlete_ace_data/schemas/v1 --base-url https://raw.githubusercontent.com/mikeymicrophone/athlete_ace_data/main/schemas/v1 --check
```

`RAILS_ENV=test CHECK=1 bundle exec rails seeds:schema_contract` checks model/contract drift. The exporter derives envelope fields from the shared Reader and fails if those declarations diverge. Generated schemas are self-contained and require no remote `$ref` downloads. Their `$id` URLs point to this repository's `main` branch. The source contract is shared with the `pseudo` branch; simulation data remains separate. When publishing from an isolated data checkout, copy the generated contract there and set the exporter output to that checkout's `schemas/v1` directory. Prelaunch schema details can continue to evolve alongside consumers.
